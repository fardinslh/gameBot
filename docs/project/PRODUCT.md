# Understand the Crown & Coin product

Crown & Coin gives a player a persistent medieval Kingdom, a standing Army led by Commanders, and a repeatable PvP return loop. The current product focuses on readable mobile progression rather than broad feature count.

## Player fantasy

The player acts as the ruler of a growing Kingdom. They collect production, improve structures, train troops, develop Heroes as Commanders, raid another Kingdom, defend stored resources, and return for Revenge after a successful enemy attack.

The visual direction uses stylized-realistic medieval fantasy artwork. The Castle anchors the composition. Terrain, paths, forest, rock, work yards, warm windows, restrained motion, and local building props support a premium mobile strategy presentation.

## Implemented product loop

The current Web build supports:

1. Open the Kingdom and receive authoritative balances and progression state
2. Collect up to eight hours of server-timed production
3. Upgrade nine persistent buildings under Castle-level gates
4. Upgrade Knight, Ranger, and Mage, then save their Raid Team order
5. Train Infantry, Archers, or Cavalry and arrange three Commander-led Army squads
6. Search for an opponent through server matchmaking
7. Watch a deterministic auto-battle replay generated by the API
8. Receive authoritative loot and Trophy changes
9. Review incoming attacks and consume an eligible Revenge once

The game stores all persistent state in PostgreSQL.

The Army foundation now drives production Raid and Revenge through deterministic rules version 2. Stored Hero-based rules-version-1 battles remain replay-compatible.

## Progression role

The first session teaches the existing loop through real Collect, building Upgrade, and standard Raid actions; it creates no tutorial economy. Progress is durable and skippable. A permanent bilingual Game Guide remains available afterward, while audio adds atmosphere without gating gameplay.

Castle level controls building unlocks and feature metadata. Building upgrades increase production, capacity through Castle level, special Kingdom effects, and Kingdom XP. Kingdom Level summarizes total building investment and does not unlock gameplay.

Progressive Kingdom Expansion changes the world at Castle levels 2 through 5. New structures receive a local environment treatment and join the active camera only after the server marks them unlocked.

## PvP role

Raid connects progression to the return loop. Match Offers limit target substitution and expire after 180 seconds. The API snapshots both teams, simulates the battle from a stored seed and rules version, then settles resources and Trophies in one transaction.

A successful incoming Raid against a real player creates a 24-hour Revenge opportunity. Revenge uses current Army Formations and balances at execution time, reuses the versioned battle dispatcher, and cannot create another Revenge target.

## Platform strategy

The intended distribution sequence is Bale Mini App, Telegram Mini App, then Web/global distribution. The current implementation supports Web development identity only. Platform interfaces and database enums reserve the boundary without coupling domain services to a platform SDK.

## Long-term direction

The repository records Guild, Shop, Season, leaderboard, platform authentication, payments, and external notification delivery as deferred scope. No current schema, controller, or client feature implements those systems.

Monetization rules have not been designed in code. Do not infer prices, premium resource purchases, payment providers, or reward ads from the `PURCHASE` transaction enum or platform payment interface.
